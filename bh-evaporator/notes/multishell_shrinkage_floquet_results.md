# Multi-Shell Shrinkage Floquet Results

## Purpose

Strengthen the shrinkage/autonomy part of the model.

The older reversible shrinkage check showed that one threshold update:

```text
if A + emitted_bin >= Delta M:
  L -> L - 1
  shell_label -> shrink_record
```

can be injective if the emitted radiation and shrink record are retained.

This diagnostic asks a stronger question:

```text
Can repeated emissions drive multiple possible shell shrinkages through an
internal accumulator register, without an external "now shrink" instruction?
```

## Script

```text
sim/multishell_shrinkage_floquet.py
```

Output:

```text
sim/data/multishell_shrinkage_floquet_sample.csv
sim/data/multishell_shrinkage_floquet_summary.csv
```

## Register Structure

Registers:

```text
L:
  active droplet size.

A:
  emitted-energy accumulator.

shell_labels:
  all nested shell labels for L=1,...,L0.

emitted_bin:
  incoming hard energy bin for one repeated-interaction step.

radiation_record:
  emitted-bin history.

shrink_record:
  sequence of shell labels transferred out when thresholds fire.
```

At each step:

```text
A' = A + emitted_bin.
```

If:

```text
A' < Delta M,
```

then:

```text
L unchanged;
A -> A';
shell labels unchanged.
```

If:

```text
A' >= Delta M,
```

then:

```text
L -> L - 1;
A -> A' - Delta M;
current shell label -> shrink_record;
that shell slot is zeroed.
```

The rule is the same at every step. Shrinkage is conditional on the internal
accumulator.

## Exhaustive Check

Parameters:

```text
L0 = 3
q = 2
Delta M = 8 integer units
A mod 8
emitted bins = {1,2,3}
sequence length = 4
```

The script enumerates:

```text
all initial accumulators;
all nested shell labels;
all emitted-bin sequences of length 4.
```

It checks injectivity of the full map:

```text
(initial registers, emitted sequence)
  ->
(final L, final A, remaining shell labels, radiation record, shrink record).
```

## Result

```text
inputs                 = 165888
unique outputs         = 165888
injective              = True
total shrink events    = 165888
max shrinks / sequence = 2

zero-shrink outputs    = 13312
one-shrink outputs     = 139264
multi-shrink outputs   = 13312
```

So the repeated threshold rule is an injective finite-register update even
when:

```text
1. shrinkage may or may not occur;
2. different emitted-bin histories are allowed;
3. more than one shell can shrink during the sequence;
4. all nested shell labels are present.
```

## What This Improves

This removes a narrower staging objection.

Before:

```text
shell shrinkage was represented as a one-step reversible update.
```

Now:

```text
the same internal accumulator rule can be iterated across multiple emissions
and multiple possible shell shrinkages.
```

The update is still a designed repeated-interaction rule, but it is no longer:

```text
an externally scheduled shell transfer at a chosen time.
```

It is:

```text
a reversible conditional finite-register subdynamics.
```

## What This Does Not Yet Prove

This is not a Hamiltonian derivation.

Remaining caveats:

```text
1. The update is a permutation/isometry, not generated by one H_total.
2. The energy bins are integer toy bins in this diagnostic.
3. It has not yet been composed directly with the explicit hard-register
   state-vector simulation.
4. The accumulator threshold is still a model rule.
```

But it is a useful F15 upgrade:

```text
the shrinkage trigger can be internal and reversible over repeated steps.
```
